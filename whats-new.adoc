=== Charges de travail des bases de données



==== Configurations de base de données incluses dans un tableau de bord bien architecturé

Le tableau de bord à l’architecture optimisée inclut désormais des recommandations pour les configurations de votre base de données, vous permettant d’évaluer et d’optimiser votre installation selon les meilleures pratiques. Les premières configurations affichées dans le tableau de bord sont :

* Hiérarchisation des données froides
* Efficacités du stockage
* Stratégie de snapshot
* marge de capacité SSD
* Gestion de l'espace des périphériques de blocs
* Type de OS
* Faire correspondre le type de système d'exploitation du périphérique de bloc à l'hôte
* Périphériques de bloc inactifs (LUNs)
* Placement des fichiers de données (.mdf)
* Emplacement des fichiers journaux (.ldf)
* État des E/S multipath
* Délai d'attente des E/S multivoies
* quorum du cluster
* Dimensionnement optimal des ressources de calcul


Sélectionnez le menu principal dans la console Workload Factory, puis sélectionnez *Well-architected* pour trouver le tableau de bord Well-architected.

==== Améliorations apportées au diagramme du groupe initiateur

Le diagramme affichant les groupes d'initiateurs pour les périphériques de stockage bloc sur la page « Gérer l'accès client » contient désormais plus de détails sur les hôtes. Lorsque vous survolez un hôte dans le diagramme, ses détails s'affichent, notamment le nom de l'hôte, l'ID d'instance, le type de workload, la région et le nom qualifié iSCSI (IQN).



==== Amélioration des e-mails pour les problèmes bien architecturés

Le nouveau format des e-mails fournit davantage de détails et de contexte sur les problèmes de configuration détectés par Workload Factory. L'e-mail indique le nombre de ressources analysées, le nombre de celles présentant des alertes ou des problèmes critiques, ainsi que la nature de ces problèmes. L'e-mail contient également un lien vers le tableau de bord Well-Architected de FSx for ONTAP afin que vous puissiez résoudre les problèmes immédiatement.



==== Améliorations du tableau de bord bien architecturé



===== Prise en charge de certaines vérifications de configuration

Vous pouvez exécuter manuellement une analyse sur les configurations sélectionnées afin d'analyser uniquement les configurations qui vous intéressent et de réduire ainsi le temps d'attente.



===== Nouvelles recommandations dans l'analyse bien architecturée

Workload Factory inclut désormais les configurations suivantes dans l'analyse bien architecturée pour les systèmes de fichiers FSx for ONTAP :

Pour les workloads de stockage :

* *Connecter l'hôte au nœud de basculement* : vérifie si les hôtes sont connectés au nœud de basculement dans un système de fichiers FSx for ONTAP actif-passif pour des raisons de fiabilité.
* *Connecter l'hôte au nœud préféré* : vérifie si les hôtes sont connectés à leurs périphériques bloc en utilisant le nœud préféré pour optimiser les performances.
* *Lacune de la détection multi-périphériques ARP/AI* : ARP/AI assure une protection complète lorsqu'un volume n'a qu'un seul périphérique de bloc qui lui est associé. Si un volume a plusieurs périphériques de bloc associés, Workload Factory déplace ces périphériques de bloc vers de nouveaux volumes afin que chaque volume n'ait qu'un seul périphérique de bloc.
* *Nettoyage des clones* : vérifie s’il existe des clones de volume datant de plus de 30 jours qui peuvent être supprimés afin d’optimiser l’utilisation du stockage et de réduire les coûts.
* *Correspondance du système d'exploitation du groupe d'initiateurs à celui de l'hôte* : vérifie si le système d'exploitation du groupe d'initiateurs (igroup) correspond à celui de l'hôte afin d'éviter les problèmes d'E/S ou de performances.


Pour les workloads Kubernetes :

* *Configuration QoS* : vérifie si les volumes persistants Kubernetes sont protégés par une politique QoS ONTAP pour optimiser les performances.
* *VM de stockage Kubernetes dédiée* : vérifie si le système de fichiers utilise une VM de stockage dédiée pour les workloads Kubernetes afin d’améliorer l’isolation et de simplifier la gestion du stockage.
* *Règles d'export Kubernetes dédiées* : vérifie si chaque volume persistant Kubernetes possède des règles d'export dédiées qui autorisent uniquement l'accès depuis les nœuds worker du cluster.
* *CHAP bidirectionnel pour les backends iSCSI Kubernetes* : vérifie si les backends iSCSI Trident ont l’authentification CHAP mutuelle activée pour des raisons de sécurité.
* *Désactiver `showmount` sur la VM de stockage d'application* : vérifie si `showmount` est désactivé sur la VM de stockage d'application afin d'empêcher les clients de lister les exports auxquels ils ne peuvent pas accéder.


Pour les workloads de base de données :

* *Stratégie de snapshot SAP HANA* : vérifie si la stratégie de snapshot est définie sur « Aucun » pour les volumes SAP HANA afin de réduire les coûts de stockage et d’améliorer les performances des données actives de la base de données.
* *Politique de snapshot MySQL* : vérifie si la politique de snapshot est définie sur « Aucun » pour les volumes MySQL afin de réduire les coûts de stockage et d’améliorer les performances des données actives de la base de données.
* *Politique de snapshot PostgreSQL* : vérifie si la politique de snapshot est définie sur « Aucun » pour les volumes PostgreSQL afin de réduire les coûts de stockage et d’améliorer les performances des données de base de données actives.




===== Valeurs actuelles et recommandées pour les configurations

Vous pouvez consulter les valeurs actuelles et recommandées de certaines configurations non optimisées dans le tableau de bord Well-Architected. Cela vous indique la valeur recommandée avant de la corriger.

* Hiérarchisation des données froides
* Stratégie de snapshot
* marge de capacité SSD




==== Optimisation des coûts



===== Prévisions et analyses de coûts

Vous pouvez désormais prévoir les coûts de vos systèmes de fichiers FSx for ONTAP grâce à la fonctionnalité de prévision des coûts. Cela vous permet de planifier votre budget et d'optimiser efficacement vos ressources. Vous pouvez également consulter des informations sur vos coûts et vos habitudes d'utilisation afin d'identifier des opportunités d'optimisation des coûts.



===== Rapports de coûts et d'utilisation AWS (CUR)

Workload Factory utilise désormais AWS Cost and Usage Reports (CUR) au lieu d'AWS Cost Explorer pour fournir des relevés de facturation détaillés livrés dans des compartiments S3 appartenant aux clients. CUR offre une meilleure granularité des coûts et constitue la base pour des cas d'utilisation avancés de FinOps, de refacturation et d'allocation des coûts.



==== Améliorations de la migration des machines virtuelles de stockage

Workload Factory fournit des conseils améliorés dans l'interface utilisateur pour la migration des machines virtuelles de stockage. Cela comprend des instructions étape par étape et une exécution de test avant de valider la migration en production.

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-replication.html["Apprenez-en davantage sur la migration des machines virtuelles de stockage"]



==== Amélioration des notifications par e-mail concernant le délai de réplication

En cas de grand nombre d'événements de retard de réplication liés, Workload Factory les regroupe automatiquement dans une seule notification par e-mail afin que vous ne soyez pas submergé de notifications.



==== Amélioration automatique de la gestion de la capacité

Vous pouvez désormais activer les notifications automatiques de gestion de la capacité pour essayer la fonctionnalité avant de demander à Workload Factory de gérer automatiquement votre capacité. Vous serez averti lorsque votre système de fichiers manquera de capacité.



==== Points de décision relatifs au débit

Vous pouvez désormais consulter les recommandations de débit client et les points de décision d'automatisation. Survolez un point de décision pour afficher des détails, tels que le SKU actuel et recommandé ou les métriques dont les seuils sont dépassés dans la fenêtre temporelle (%).



==== Support Bedrock géré par le client pour la classification

Workload Factory vous permet désormais d’utiliser votre propre configuration Amazon Bedrock pour la classification du balisage de workload. Vous pouvez fournir votre propre point de terminaison Bedrock et vos identifiants afin que les requêtes de classification s’exécutent via votre propre configuration Bedrock.

==== Prise en charge des instances i7i.metal-24xl et i7i.metal-48xl dans le calculateur de coût total de possession (TCO) d'EVS

Le calculateur de coût total de possession (TCO) d'EVS prend désormais en charge les instances EC2 AWS i7i.metal-24xl et i7i.metal-48xl comme hôtes de cluster. Par rapport aux configurations i4i.metal, les instances i7i.metal-24xl permettent de réduire le coût initial d'EVS d'environ 33 % pour le calcul et de 25 % pour le stockage vSAN.

Le calculateur compare tous les types d'instances et sélectionne automatiquement l'option la plus économique. Une nouvelle section de comparaison affiche les configurations hôtes EVS côte à côte, facilitant ainsi le choix de la configuration la mieux adaptée à vos besoins.

link:https://docs.netapp.com/us-en/workload-vmware/calculate-evs-savings.html["Calculez les économies estimées pour EVS"]

Les tableaux de bord personnalisés facilitent désormais la gestion de votre travail.

==== Découverte étendue du balisage des charges de travail pour les services AWS

Workload Factory détecte désormais davantage de services AWS pour le balisage des workloads, étendant ainsi la prise en charge des ressources pouvant être balisées. Il peut désormais identifier les ressources Amazon EKS et Amazon WorkSpaces et les inclure dans le système de balisage afin qu'elles soient disponibles pour le balisage.



==== Améliorations du tableau de bord des coûts

Le tableau de bord des coûts inclut désormais une section de synthèse destinée aux dirigeants qui offre une vue d'ensemble des dépenses de votre organisation, vous aidant à comprendre et à gérer rapidement les coûts. Ask Me, l'assistant IA de Workload Factory, peut fournir des informations et des recommandations supplémentaires en fonction de vos données de coûts. Vous pouvez interagir avec Ask Me pour obtenir des explications détaillées et des suggestions pour optimiser vos coûts.

De plus, vous pouvez filtrer les données de coût par un ou plusieurs systèmes de fichiers et un ou plusieurs volumes au sein d’un système de fichiers. Lorsque des filtres sont appliqués, Workload Factory affiche :

* Coût total estimé par mois
* Coût estimé par Gio/mois
* Ventilation détaillée des coûts par service


Toutes les informations relatives aux coûts proviennent directement de l'API AWS Cost Explorer, à l'exception de l'allocation des coûts au niveau du système de fichiers et du volume ; Workload Factory estime l'allocation des coûts au niveau du système de fichiers et du volume.



==== Accès au tableau de bord bien architecturé

Vous pouvez accéder au tableau de bord bien architecturé depuis le menu principal de la console Workload Factory et depuis un système de fichiers. Pour trouver le tableau de bord bien architecturé depuis le menu principal, sélectionnez le menu principal, puis sélectionnez *Well-architected*.

image:workload-fsx-ontap/well-architected-menu-option.png["Option de menu bien conçue dans la console NetApp Workload Factory"]



==== Nouvelles recommandations dans l'analyse bien architecturée

Workload Factory inclut désormais les configurations suivantes dans l'analyse bien architecturée pour les systèmes de fichiers FSx for ONTAP :

* *Configuration de la gestion de l'espace du volume* : il est recommandé d'activer la gestion coordonnée de l'espace du volume pour les volumes FSx pour ONTAP.
* *Intégration FSx à AWS MGN* : recommande d’appliquer la configuration de préparation AWS MGN requise aux systèmes de fichiers FSx for ONTAP sélectionnés.


link:https://docs.netapp.com/us-en/workload-fsx-ontap/configuration-analysis.html["En savoir plus sur les recommandations de bonne pratique pour vos systèmes de fichiers FSx for ONTAP."]



==== Améliorations de l'explorateur de volumes

L'explorateur de volumes est un emplacement central de la console Workload Factory où vous pouvez afficher et gérer tous vos volumes sur différents systèmes de fichiers. Il fournit des informations détaillées sur chaque volume, notamment ses performances, son utilisation et son état de protection. Les améliorations de cette version incluent la sélection des charges de travail, l'affichage de la latence des volumes et l'état ARP/AI des volumes.



===== L'explorateur de volumes prend en charge la sélection de la charge de travail

Workload Factory sélectionne par défaut une charge de travail en fonction des caractéristiques du volume et de ses modèles d'utilisation. Vous pouvez désormais modifier la charge de travail d'un ou plusieurs volumes depuis Volumes explorer.



===== L'explorateur de volumes affiche la latence du volume

L'explorateur de volumes affiche l'état de la latence des volumes avec les statuts suivants : non configuré, dans le seuil et dépassé. Ces statuts vous aident à identifier et à corriger les goulots d'étranglement des performances au niveau du volume.



===== L'explorateur de volumes affiche l'état ARP/AI des volumes dans tous les systèmes de fichiers

L'écran de l'explorateur de volumes inclut désormais une fiche avec l'état de la protection autonome contre les ransomwares avec IA (ARP/AI) de NetApp pour les volumes de tous vos systèmes de fichiers. La fiche affiche le nombre de volumes protégés et indique si des volumes sont à risque. À partir de la fiche, vous pouvez *Analyze attacks* pour examiner les menaces potentielles liées aux ransomwares et prendre les mesures appropriées pour sécuriser vos données.

image:workload-fsx-ontap/volumes-explorer-arp-ai-card.png["La capture d'écran montre une nouvelle fiche dans l'écran de l'explorateur de volumes, affichant l'état ARP/AI des volumes sur tous les systèmes de fichiers. La fiche indique le nombre de volumes protégés et les volumes à risque. Les utilisateurs peuvent sélectionner le texte Analyze attacks pour examiner les attaques suspectées et prendre les mesures appropriées afin de sécuriser leurs données."]

link:https://docs.netapp.com/us-en/workload-fsx-ontap/ransomware-protection.html["Apprenez-en davantage sur la protection contre les ransomwares."]



==== Notification par e-mail pour les relations de réplication non saines

Lorsque l'état d'une relation de réplication est *défaillant*, Workload Factory envoie une notification par e-mail toutes les 24 heures tant que la relation reste défaillante. Les notifications de rappel cessent dès que la relation redevient saine.



==== Prise en charge des identifiants ONTAP restreints pour AIOps

Workload Factory prend en charge deux types d’identifiants ONTAP pour un système de fichiers FSx for ONTAP : principaux et restreints. Par défaut, un système de fichiers utilise les identifiants ONTAP principaux. Nous utilisons les identifiants restreints uniquement pour les opérations d’IA (AIOps) telles que Rule builder, Custom dashboards et Ask Me, notre assistant IA. Vous pouvez désormais ajouter vos propres identifiants, à l’aide d’un nom d’utilisateur et d’un mot de passe ou d’un ARN secret, afin de restreindre l’accès aux fonctionnalités AIOps.

link:https://docs.netapp.com/us-en/workload-fsx-ontap/manage-file-system-settings.html["Gérer les identifiants ONTAP pour un système de fichiers FSx for ONTAP"]



==== Sélection de la charge de travail lors de la création du volume

Workload Factory inclut désormais un champ *Workloads* lors de la création d'un volume, vous permettant de sélectionner la charge de travail à associer au volume. Cela garantit que le volume est optimisé pour la charge de travail prévue dès sa création.

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-volume.html["Créez un volume dans la console Workload Factory"]



==== FlexCache amélioration du mode d'écriture

Workload Factory reconnaît désormais le mode d'écriture FlexCache® favori pour les volumes et recommande de le modifier si nécessaire afin d'optimiser les performances.



==== Lier la documentation de support

Toute la documentation relative aux liens est désormais traitée dans la documentation d'installation et d'administration de Workload Factory. Vous pouvez toujours vous référer à link:https://docs.netapp.com/us-en/workload-fsx-ontap/links-overview.html["Découvrez les liens NetApp Workload Factory"] de la documentation Workload Factory FSx for ONTAP et trouver des liens vers les pages pertinentes dans la documentation d'installation et d'administration.

link:https://docs.netapp.com/us-en/workload-setup-admin/create-link.html["En savoir plus sur la configuration des liens dans la console Workload Factory."^]



==== Découverte des relations entre hôtes et stockages entre régions

Workload Factory prend désormais en charge la recherche de connexions entre les hôtes et le stockage dans plusieurs régions AWS dans le cadre du service d'étiquetage des charges de travail. Il peut identifier et relier les hôtes et les ressources de stockage entre les régions, y compris en mappant les adresses IP entre les régions, afin que les relations entre les hôtes et le stockage soient correctement étiquetées et classées.



==== Amélioration de la précision de l'identification de la charge de travail et de l'hôte

Workload Factory identifie et classe désormais plus précisément les charges de travail et les hôtes dans le service d’étiquetage des charges de travail. Les méthodes de détection mises à jour réduisent les erreurs de classification et fournissent des résultats d’étiquetage et de classification plus précis.



==== Amélioration de la visibilité du système de fichiers dans l'interface

Workload Factory offre désormais une vue plus claire de vos systèmes de fichiers dans l’interface. Vous pouvez consulter les tendances d’utilisation de la capacité et du débit des SSD, les résumés des charges de travail et les informations détaillées sur la configuration directement depuis la vue d’ensemble du système de fichiers. Workload Factory identifie et classe désormais plus précisément les charges de travail et les hôtes dans le service d’étiquetage des charges de travail. Les méthodes de détection mises à jour réduisent les erreurs de classification et fournissent des résultats d’étiquetage et de classification plus précis.

==== Agents d'IA pour Workload Factory

Workload Factory AIOps utilise l'IA pour analyser votre environnement et recommander des améliorations. Avec votre accord, il peut également effectuer des actions à l'aide des identifiants et des autorisations que vous avez configurés. Des agents d'IA analysent votre environnement, vous aidant à identifier les risques, à améliorer les workloads et à résoudre les problèmes dans Workload Factory et Slack.

Accédez aux agents d'IA dans la nouvelle section *Explore Agents* de Ask Me. Par défaut, les agents fonctionnent en mode lecture seule et fournissent des recommandations et des analyses.

Utilisez *Agents settings* pour contrôler le fonctionnement des agents. Vous pouvez :

* Choisissez le mode lecture seule ou lecture-écriture
* Sélectionnez les identifiants que les agents peuvent utiliser
* Ajouter des instructions personnalisées
* Ajustez le niveau de détail des réponses


Ces contrôles supplémentaires vous offrent une meilleure visibilité et un contrôle accru. En mode lecture-écriture, les agents doivent obtenir votre approbation avant d’apporter des modifications à AWS, ONTAP ou aux API prises en charge. Vous pouvez également choisir le niveau de détail à afficher dans les réponses, notamment les informations relatives au raisonnement de l’agent et, dans Slack, à l’activité de ses outils.

Les agents prennent également en charge les environnements multi-comptes et une configuration simplifiée. Un seul agent peut fonctionner en toute sécurité sur plusieurs comptes AWS avec plusieurs identifiants.

link:https://docs.netapp.com/us-en/workload-setup-admin/learn-agent.html["Découvrez les agents IA"]

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-agent-settings.html["Gérer les paramètres des agents"]



==== Tâches planifiées dans Ask Me

Vous pouvez désormais personnaliser une invite dans la conversation Ask Me pour créer des tâches planifiées. Utilisez les tâches planifiées pour demander à Ask Me d'effectuer des vérifications régulières et d'envoyer des mises à jour dans la conversation selon la planification que vous définissez.

Exemples d'invites :

* Vérifiez toutes les heures l'état de santé et le statut du cycle de vie de tous les systèmes de fichiers FSx for NetApp ONTAP afin de détecter les problèmes le plus tôt possible.
* Répertoriez tous les systèmes de fichiers AWS FSx accessibles toutes les heures afin de maintenir un inventaire à jour.


link:https://docs.netapp.com/us-en/workload-setup-admin/workload-factory-overview.html#features["En savoir plus sur Ask Me"]



==== Prise en charge du stockage dans Ask Me

Ask Me prend désormais en charge FSx for ONTAP et Google Cloud NetApp Volumes. Bénéficiez de la même expérience de chat pour obtenir des réponses et des informations sur l’ensemble de vos environnements de stockage pris en charge.

link:https://docs.netapp.com/us-en/workload-setup-admin/workload-factory-overview.html#features["En savoir plus sur Ask Me"]



==== Mise à jour des notifications

Les notifications de NetApp Console sont désormais activées par défaut. Les utilisateurs de NetApp Console recevront automatiquement les notifications de Workload Factory sans configuration supplémentaire.

link:https://docs.netapp.com/us-en/workload-setup-admin/configure-notifications.html["Notifications de Workload Factory"]



==== Courriel de notification de création de lien

Workload Factory vous rappelle désormais de finaliser l'association des liens après avoir ajouté avec succès des identifiants. Bien que les identifiants permettent la découverte des ressources, les fonctionnalités avancées d'ONTAP nécessitent l'association des liens avec les systèmes de fichiers découverts. Vous recevrez la notification par e-mail une fois par semaine, le lundi. Après avoir finalisé l'association des liens, les notifications s'arrêtent.



==== Notifications de version des liens Lambda et guide de mise à niveau

Workload Factory vous avertit désormais lorsqu'un lien Lambda n'utilise pas la dernière image disponible. Si les mises à jour automatiques ne sont pas prises en charge pour un lien, la notification indique lorsqu'une version plus récente est disponible.

Vous pouvez consulter les instructions de mise à niveau sur la page Liens. Ces instructions expliquent comment mettre à jour manuellement l'image du lien Lambda et activer les mises à niveau automatiques lorsqu'elles sont disponibles. Maintenir les liens à jour vous permet de bénéficier des dernières fonctionnalités, de corriger les problèmes connus et d'appliquer les mises à jour de sécurité les plus récentes.

Vous recevez également une alerte dans le tableau de bord FSx for ONTAP lorsqu'une version plus récente du lien est disponible pour un lien qui ne prend pas en charge les mises à niveau automatiques.

==== Notifications améliorées de la capacité SSD

Les notifications de gestion de la capacité SSD incluent désormais des messages d'erreur détaillés pour faciliter le dépannage des échecs d'automatisation. Des notifications sont envoyées en cas d'augmentation de capacité réussie, d'erreurs lors des opérations d'augmentation, d'échecs de vérification de capacité, d'alertes de seuil et de recommandations. Les détails des erreurs comprennent des raisons d'échec spécifiques, telles que des autorisations manquantes, des mises à jour simultanées en cours, des périodes de refroidissement AWS ou des problèmes de récupération des métriques CloudWatch.

link:https://docs.netapp.com/us-en/workload-eda/learn-overview-dashboard.html["Découvrez la gestion de la capacité des SSD"^].



==== Période d’une semaine pour les graphiques de latence

Les graphiques d'analyse de la latence prennent désormais en charge une période d'une semaine, en plus des options existantes (1 heure, 3 heures, 12 heures, 24 heures, 72 heures). Utilisez la vue hebdomadaire pour identifier les schémas et les tendances à plus long terme du comportement de latence du volume.

link:https://docs.netapp.com/us-en/workload-eda/task-analyze-latency-trends.html["En savoir plus sur l'analyse des tendances de latence"^].



==== Amélioration de la visibilité du système de fichiers dans l'interface

Workload Factory vous offre désormais une vue plus claire de vos systèmes de fichiers dans l’interface. Vous pouvez consulter les tendances d’utilisation de la capacité et du débit des SSD, les résumés des charges de travail et des informations de configuration détaillées directement depuis la vue d’ensemble du système de fichiers.

==== Améliorations apportées au diagramme du groupe initiateur

Le diagramme affichant les groupes d'initiateurs pour les périphériques de stockage bloc sur la page « Gérer l'accès client » contient désormais plus de détails sur les hôtes. Lorsque vous survolez un hôte dans le diagramme, ses détails s'affichent, notamment le nom de l'hôte, l'ID d'instance, le type de workload, la région et le nom qualifié iSCSI (IQN).



==== Améliorations du tableau de bord des coûts

Le tableau de bord des coûts inclut désormais une section de synthèse destinée aux dirigeants qui offre une vue d'ensemble des dépenses de votre organisation, vous aidant à comprendre et à gérer rapidement les coûts. Ask Me, l'assistant IA de Workload Factory, peut fournir des informations et des recommandations supplémentaires en fonction de vos données de coûts. Vous pouvez interagir avec Ask Me pour obtenir des explications détaillées et des suggestions pour optimiser vos coûts.

De plus, vous pouvez filtrer les données de coût par un ou plusieurs systèmes de fichiers et un ou plusieurs volumes au sein d’un système de fichiers. Lorsque des filtres sont appliqués, Workload Factory affiche :

* Coût total estimé par mois
* Coût estimé par Gio/mois
* Ventilation détaillée des coûts par service


Toutes les informations relatives aux coûts proviennent directement de l'API AWS Cost Explorer, à l'exception de l'allocation des coûts au niveau du système de fichiers et du volume ; Workload Factory estime l'allocation des coûts au niveau du système de fichiers et du volume.



==== Accès au tableau de bord bien architecturé

Vous pouvez accéder au tableau de bord bien architecturé depuis le menu principal de la console Workload Factory et depuis un système de fichiers. Pour trouver le tableau de bord bien architecturé depuis le menu principal, sélectionnez le menu principal, puis sélectionnez *Well-architected*.

image:workload-fsx-ontap/well-architected-menu-option.png["Option de menu bien conçue dans la console NetApp Workload Factory"]



==== Nouvelles recommandations dans l'analyse bien architecturée

Workload Factory inclut désormais les configurations suivantes dans l'analyse bien architecturée pour les systèmes de fichiers FSx for ONTAP :

* *Configuration de la gestion de l'espace du volume* : il est recommandé d'activer la gestion coordonnée de l'espace du volume pour les volumes FSx pour ONTAP.
* *Intégration FSx à AWS MGN* : recommande d’appliquer la configuration de préparation AWS MGN requise aux systèmes de fichiers FSx for ONTAP sélectionnés.


link:https://docs.netapp.com/us-en/workload-fsx-ontap/configuration-analysis.html["En savoir plus sur les recommandations de bonne pratique pour vos systèmes de fichiers FSx for ONTAP."]



==== Améliorations de l'explorateur de volumes

L'explorateur de volumes est un emplacement central de la console Workload Factory où vous pouvez afficher et gérer tous vos volumes sur différents systèmes de fichiers. Il fournit des informations détaillées sur chaque volume, notamment ses performances, son utilisation et son état de protection. Les améliorations de cette version incluent la sélection des charges de travail, l'affichage de la latence des volumes et l'état ARP/AI des volumes.



===== L'explorateur de volumes prend en charge la sélection de la charge de travail

Workload Factory sélectionne par défaut une charge de travail en fonction des caractéristiques du volume et de ses modèles d'utilisation. Vous pouvez désormais modifier la charge de travail d'un ou plusieurs volumes depuis Volumes explorer.



===== L'explorateur de volumes affiche la latence du volume

L'explorateur de volumes affiche l'état de la latence des volumes avec les statuts suivants : non configuré, dans le seuil et dépassé. Ces statuts vous aident à identifier et à corriger les goulots d'étranglement des performances au niveau du volume.



===== L'explorateur de volumes affiche l'état ARP/AI des volumes dans tous les systèmes de fichiers

L'écran de l'explorateur de volumes inclut désormais une fiche avec l'état de la protection autonome contre les ransomwares avec IA (ARP/AI) de NetApp pour les volumes de tous vos systèmes de fichiers. La fiche affiche le nombre de volumes protégés et indique si des volumes sont à risque. À partir de la fiche, vous pouvez *Analyze attacks* pour examiner les menaces potentielles liées aux ransomwares et prendre les mesures appropriées pour sécuriser vos données.

image:workload-fsx-ontap/volumes-explorer-arp-ai-card.png["La capture d'écran montre une nouvelle fiche dans l'écran de l'explorateur de volumes, affichant l'état ARP/AI des volumes sur tous les systèmes de fichiers. La fiche indique le nombre de volumes protégés et les volumes à risque. Les utilisateurs peuvent sélectionner le texte Analyze attacks pour examiner les attaques suspectées et prendre les mesures appropriées afin de sécuriser leurs données."]

link:https://docs.netapp.com/us-en/workload-fsx-ontap/ransomware-protection.html["Apprenez-en davantage sur la protection contre les ransomwares."]



==== Notification par e-mail pour les relations de réplication non saines

Lorsque l'état d'une relation de réplication est *défaillant*, Workload Factory envoie une notification par e-mail toutes les 24 heures tant que la relation reste défaillante. Les notifications de rappel cessent dès que la relation redevient saine.



==== Prise en charge des identifiants ONTAP restreints pour AIOps

Workload Factory prend en charge deux types d’identifiants ONTAP pour un système de fichiers FSx for ONTAP : principaux et restreints. Par défaut, un système de fichiers utilise les identifiants ONTAP principaux. Nous utilisons les identifiants restreints uniquement pour les opérations d’IA (AIOps) telles que Rule builder, Custom dashboards et Ask Me, notre assistant IA. Vous pouvez désormais ajouter vos propres identifiants, à l’aide d’un nom d’utilisateur et d’un mot de passe ou d’un ARN secret, afin de restreindre l’accès aux fonctionnalités AIOps.

link:https://docs.netapp.com/us-en/workload-fsx-ontap/manage-file-system-settings.html["Gérer les identifiants ONTAP pour un système de fichiers FSx for ONTAP"]



==== Sélection de la charge de travail lors de la création du volume

Workload Factory inclut désormais un champ *Workloads* lors de la création d'un volume, vous permettant de sélectionner la charge de travail à associer au volume. Cela garantit que le volume est optimisé pour la charge de travail prévue dès sa création.

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-volume.html["Créez un volume dans la console Workload Factory"]



==== FlexCache amélioration du mode d'écriture

Workload Factory reconnaît désormais le mode d'écriture FlexCache® favori pour les volumes et recommande de le modifier si nécessaire afin d'optimiser les performances.

==== Actions sur les volumes disponibles dans l'explorateur de volumes

Toutes les actions sur les volumes sont directement accessibles depuis l'explorateur de volumes pour un ou plusieurs volumes. Cela permet d'effectuer plus rapidement des opérations au niveau des volumes. Les actions sur les volumes incluent la modification des paramètres de volume, la gestion des snapshots et l'exécution d'autres tâches sur les volumes sans quitter l'explorateur de volumes. Vous pouvez également accéder à ces actions depuis l'onglet Volumes dans la vue d'ensemble du système de fichiers FSx for ONTAP.
